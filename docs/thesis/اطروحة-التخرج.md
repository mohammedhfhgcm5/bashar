# الفصل الأول — المقدمة والإطار العام

## 1.1 المقدمة

تُعدّ مشاريع التخرج ركيزةً أساسية في المسيرة الأكاديمية، إذ تتيح توظيف المعارف النظرية في حلول تقنية حقيقية. وفي ظل تطور تقنية المعلومات والرؤية الحاسوبية، باتت الحاجة ماسّة إلى منصات رقمية توحّد توثيق الأضرار العقارية ومراجعتها وتوزيع المساعدات.

نقدّم في هذا المشروع منصة إلكترونية لتوثيق الأضرار: رفع البلاغ مع الموقع والصور، تقييم أولي بنموذج كشف أجسام، مراجعة المشرف، ثم تسجيل المساعدات على البلاغات المعتمدة. عملنا على المشروع معاً كفريق ثنائي؛ لذلك نستخدم في هذه الأطروحة صيغة «نحن».

## 1.2 الهدف من المشروع

نهدف إلى:

1. تطوير منصة ويب تنظّم دورة حياة البلاغ من المسودة حتى الاعتماد أو الرفض.
2. ربط المواطن/المقيم بالمشرف ومنظمة الإغاثة بصلاحيات واضحة.
3. أتمتة التقييم الأولي عبر YOLOv8 بصيغة ONNX مع إبقاء الاعتماد بيد المشرف.
4. بناء خريطة وإحصاءات تساعد على رؤية التجمع الجغرافي ومستويات الضرر.
5. تمكين تسجيل المساعدات وربطها بالبلاغات المعتمدة.
6. اكتساب خبرة عملية في تطبيق ويب بمستوى إنتاجي (React، NestJS، Prisma، ONNX).

## 1.4 مزايا المشروع

- دورة حياة بلاغ صريحة ورمز مرجع فريد.
- تقييم متعدد الصور مع ملخص عربي وثقة وتغطية تقريبية.
- فصل الاقتراح الآلي عن اعتماد المشرف.
- خريطة حسب صلاحية الدور.
- RBAC على الخادم + سجل مراجعة.
- مساعدات مرتبطة بالبلاغ المعتمد.
- واجهة عربية متجاوبة.

# الفصل الثاني — الأدوات والتقنيات البرمجية

## 2.1 بيئة التطوير

### 2.1.1 Visual Studio Code / Cursor
محرر واسع الانتشار مع امتدادات وتكامل Git. استخدمناه مع Cursor داخل monorepo (`apps/web`، `apps/api`، `packages/shared`).

### 2.1.2 Docker Compose
شغّلنا PostgreSQL بحاوية موحّدة حتى لا تختلف بيئة القاعدة بين أجهزتنا.

## 2.2 تقنيات الواجهة الأمامية (Frontend)

### 2.2.1 React JS
مكوّنات وHooks وVirtual DOM. بنينا بها كل الصفحات.

### 2.2.2 Vite
بناء سريع وHMR؛ بديل أفضل من CRA لمشروعنا.

### 2.2.3 Tailwind CSS
Utility-First مع دعم RTL للواجهة العربية.

### 2.2.4 React Router
مسارات SPA مع Gate وRoleGate حسب الجلسة والدور.

### 2.2.5 TanStack React Query
تخزين مؤقت ومزامنة طلبات الـ API وحالات التحميل/الخطأ.

### 2.2.6 React Hook Form + Zod
نماذج خفيفة وتحقق بمخططات؛ Zod أيضاً في الحزمة المشتركة.

### 2.2.7 Leaflet و React-Leaflet
خريطة علامات مع تجميع، وفق سياسة القراءة.

## 2.3 تقنيات الخادم (Backend)

### 2.3.1 NestJS
Modules / Controllers / Services وDI — وحدات المصادقة والمستخدمين والمنظمات والبلاغات والرؤية والمساعدة والإحصاء.

### 2.3.2 PostgreSQL
تخزين علاقي موثوق مع فهارس على الحالة والمستوى والإحداثيات.

### 2.3.3 Prisma ORM
Schema وMigrate وعميل Type-safe لكل الكيانات والتعدادات.

### 2.3.4 JWT و Passport و bcryptjs
جلسة قصيرة العمر، حراس، تجزئة كلمات المرور، وبصمات RefreshSession.

### 2.3.5 Multer و Sharp
رفع الصور، letterbox إلى 640، وفحص محتوى الصورة.

### 2.3.6 packages/shared
أدوار، مستويات، أصناف PECCD، و`aggregateDamage` مصدر واحد للطرفين.

## 2.4 تقنيات الرؤية الحاسوبية

### 2.4.1 YOLOv8n (Ultralytics)
ستة أصناف عيوب؛ تدريب Python ثم تصدير ONNX.

### 2.4.2 ONNX Runtime
استدلال داخل Node بمزود CPU دون Python في الإنتاج.

### 2.4.3 قاعدة التجميع
عتبة ثقة 0.35، أعلى شدة ظاهرة، ثقة داعمة، تغطية شبكة 64×64.

## 2.5 متصفحات الويب
SPA عبر Chrome / Edge / Firefox / Safari الحديثة.

**خلاصة الفصل:** شرحنا كل تقنية وسبب اختيارنا لها من الواجهة حتى مسار الرؤية.

# الفصل الثالث — متطلبات النظام وتوصيفه

## 3.1 المتطلبات الوظيفية

### 3.1.1 المواطن / المقيم
حساب، بلاغ مسودة، صور، إرسال، تقييم، تطبيق المستوى المقترح، تعديل المرفوض.

### 3.1.2 المشرف
كل البلاغات، مراجعة، إدارة مستخدمين/منظمات، إحصاء، مساعدات.

### 3.1.3 المنظمة
المعتمد فقط، إنشاء مساعدة وتحديث حالتها، إحصاءات.

## 3.2 المتطلبات غير الوظيفية
أداء مقبول، أمان JWT/bcrypt/RBAC، توسعية وحدات، RTL عربي، استمرار الخدمة بدون النموذج، توافق متصفحات حديثة.

## 3.3 توصيف النظام

### 3.3.1 الأدوار
انظر جدول الأدوار في ملف Word.

### 3.3.2 قاعدة البيانات
User، RefreshSession، Organization، Property، Report، Image، VisionAssessment، ReviewLog، AidDistribution، ReportCounter.

### 3.3.3 API
Auth، Users، Organizations، Reports (+ assess/review/images/map)، Aid، Stats، Health.

## 3.4 النتائج المحققة
وحدات NestJS مكتملة، 10 كيانات، ~10 صفحات، 4 أدوار، 6 أصناف رؤية، JWT+RBAC، واجهة عربية مع خريطة.
